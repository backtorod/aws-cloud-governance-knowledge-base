# Contributing

## Contribution standard

Every substantive addition must identify its source, authority level, intended use, and limitations. Prefer links and concise interpretation over copied upstream content.

A pull request should explain:

- what changed and why;
- which source or decision supports it;
- whether the change is fact, inference, recommendation, or decision;
- affected AWS services, control modes, and lifecycle phases;
- impact on EvidenceMark schemas or integrations;
- validation performed.

## Source updates

Pin or record immutable revisions when possible. Verify licenses before reusing code or substantial text. Do not copy framework text unless redistribution is permitted.

## Review requirements

Human review is required for authority changes, framework mappings, schema-breaking changes, licensing changes, removals, and recommendations that could create material security or operational risk.
